---

Start the definition of a new project.

Do not implement it yet.

Determine:

1. Project goal.
2. Domain and project type.
3. Expected users or consumers.
4. Technology or environment constraints.
5. Expected deliverables.
6. Definition of success.

Then:

- Identify reusable templates and skills that may apply.
- Propose the initial repository documentation structure.
- Propose which project-specific skills should be copied into the repository.
- Propose an initial `AGENTS.md`.
- Produce a concise project brief/specification before implementation begins.

Prefer existing shared templates and conventions over inventing new ones.
