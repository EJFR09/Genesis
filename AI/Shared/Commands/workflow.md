Summarize the current working convention concisely.

Use this architecture:

- Warp = terminal interface
- OpenCode THINK = reasoning, learning, architecture and specifications
- OpenCode PLAN = implementation planning
- OpenCode BUILD = implementation, execution and verification
- VS Code = visual inspection and manual editing
- Repository = project-specific source of truth
- Obsidian AI knowledge base = reusable source of truth

Standard flow:

1. `/new-task` or `/new-project`
2. THINK
3. Retrieve only relevant shared knowledge
4. Create or refine the specification when needed
5. PLAN
6. BUILD
7. VERIFY
8. `/learn`
9. Distill approved reusable knowledge into Obsidian

Knowledge rules:

- Project-specific information stays in the repository.
- Reusable information belongs in Obsidian.
- Prefer deterministic paths and INDEX.md files.
- Load skills only when relevant.
- Do not write to Obsidian without approval.

Keep the explanation concise unless I ask for more detail.
